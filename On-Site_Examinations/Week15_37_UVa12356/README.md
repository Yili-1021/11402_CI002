# UVa 12356 - Army Buddies

## 問題描述
在一場慘烈的戰爭中，有一支由 $B$ 個士兵組成的部隊，士兵們由左到右依序排成一列，編號為 $1, 2, 3, \dots, B$。在剛開始時，每位士兵的左右兩邊都緊鄰著他的戰友（Buddy）。

接下來發生了 $S$ 次敵軍的局部轟炸。每次轟炸會導致編號從 $L$ 到 $R$ 的連續區間內的所有士兵全部陣亡。

作為指揮官，你的任務是在每次轟炸發生後，立刻回報**這群剛陣亡的士兵們，其最左邊倖存的戰友（即 $L$ 左邊第一個活著的人）以及最右邊倖存的戰友（即 $R$ 右邊第一個活著的人）**的編號。如果某個方向已經沒有任何人倖存，則以 `-` 代替。

---

## 解題邏輯與程式

### 核心邏輯
如果直接使用布林陣列（如 `bool alive[]`）去記錄每個人是否活著，並在每次轟炸時用迴圈將 $L$ 到 $R$ 標記為死亡、再用 `while` 迴圈往左往右尋找活人，在最壞情況下（例如每次都炸中間，或者大範圍重複轟炸），時間複雜度會退化到 $O(B \times S)$。當 $B, S \le 100000$ 時，必然會迎來超時（TLE）。

本題的精髓在於利用**雙向鏈結串列（Doubly Linked List）**的鄰居指針思想，但為了實作效率，我們不使用複雜的指標與結構，而是直接開兩個一維陣列來「虛擬」維護每個人左右兩邊活著的鄰居：
- `left_buddy[i]`：記錄編號為 `i` 的士兵，目前左邊第一個活著的戰友是誰。
- `right_buddy[i]`：記錄編號為 `i` 的士兵，目前右邊第一個活著的戰友是誰。

當一組區間 $[L, R]$ 的士兵陣亡時：
1. 這群人左方第一個活人的「右鄰居」，將跨過這群死者，直接變成這群人右方第一個活人。
2. 同理，這群人右方第一個活人的「左鄰居」，將直接變成這群人左方第一個活人。
3. **狀態更新公式**：
   - `right_buddy[left_buddy[L]] = right_buddy[R];`
   - `left_buddy[right_buddy[R]] = left_buddy[L];`



透過這種方式，我們可以直接繞過死者更新邊界，不需做任何線性掃描，即可在 $O(1)$ 的常數時間內完成一次轟炸回報。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    // 優化輸入輸出效能
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int b, s;
    while (cin >> b >> s && (b != 0 || s != 0)) {
        // 配置 1-indexed 陣列，多開空間給邊界 0 與 b + 1
        vector<int> left_buddy(b + 2);
        vector<int> right_buddy(b + 2);

        // 初始狀態下，每個人的鄰居就是相鄰的編號
        for (int i = 1; i <= b; i++) {
            left_buddy[i] = i - 1;
            right_buddy[i] = i + 1;
        }

        // 邊界哨兵（Sentinel）設定
        left_buddy[1] = 0;      // 1 的左邊沒有活人
        right_buddy[b] = 0;     // b 的右邊沒有活人

        for (int i = 0; i < s; i++) {
            int l, r;
            cin >> l >> r;

            // 1. 更新邊界倖存者的鄰居指針
            int new_left = left_buddy[l];
            int new_right = right_buddy[r];

            if (new_left != 0) right_buddy[new_left] = new_right;
            if (new_right != 0) left_buddy[new_right] = new_left;

            // 2. 輸出當前轟炸後，左邊與右邊倖存的戰友
            if (new_left == 0) cout << "*";
            else cout << new_left;

            cout << " ";

            if (new_right == 0) cout << "*";
            else cout << new_right;

            cout << "\n"; // 使用 \n 代替 endl 加速
        }
        cout << "-\n";
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(B + S)$。每組測資的初始化陣列需要 $O(B)$ 時間。隨後的 $S$ 次轟炸處理中，由於更新指標與查詢只需透過陣列索引，每次均為 $O(1)$ 的常數時間，總計 $O(S)$。因此整組測資的時間複雜度為線性的 $O(B + S)$，可在時限內超高速通過。
- **空間複雜度**：$O(B)$。主要消耗在維護左右戰友編號的兩個 `std::vector`，空間大小與士兵總數 $B$ 成線性正比。

## 心得與反思

- **靜態陣列模擬鏈結串列（Static Linked List）**：
  這題是非常優雅的資料結構變形題。傳統上想到「刪除中間區段、重新串接兩端」，直覺會想用指標建 Linked List 或直接套用 `std::list`。然而在演算法競賽中，動態 new 指標或頻繁更動節點極度耗時。改用兩個「靜態陣列」來模擬雙向鏈結的指標，既能享有 Linked List 跨越死者的 $O(1)$ 刪除優勢，又保有了陣列隨機存取的高效與簡潔，是非常厲害的實作思維。

- **哨兵（Sentinel）與邊界防禦**：
  在處理這類指針跳躍的問題時，最容易因為沒處理好「最左邊」與「最右邊」的死路而造成陣列越界。透過引入 `0` 作為哨兵節點，代表「該方向已無活人」，可以在更新指針時省去一堆繁雜的 `if(l == 1)` 或 `if(r == b)` 的特例判斷，讓主邏輯保持極致的乾淨與安全。
