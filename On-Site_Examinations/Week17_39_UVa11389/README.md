# UVa 11389 - The Bus Driver Problem

## 問題描述
某個公車營運處有 $n$ 位司機，每天要負責行駛 $n$ 條上午路線與 $n$ 條下午路線。每位司機必須被分配到**恰好一條上午路線與一條下午路線**。

政府規定，每位司機每天的總工作時數上限為 $d$ 小時。如果某位司機的上午與下午路線時數加總超過了 $d$，超出（Overtime）的每個小時，營運處就必須支付該司機 $r$ 元的加班費。

請幫營運處規劃如何分配路線，使得每天要支付給所有司機的**總加班費降到最低**？

---

## 解題邏輯與程式

### 核心邏輯
這是一題非常典型的**貪婪演算法（Greedy Algorithm）**題目。

為了讓所有人的超時加總（即所有大於 $d$ 的部分）達到最小，最直觀的直覺是「截長補短」：讓早上開很長路線的司機，下午去開最短的路線；反之，早上開短路線的司機，下午去分擔長路線。

1. **雙重反向排序**：
   - 將所有上午路線的長度由小到大排序（升序）。
   - 將所有下午路線的長度由大到小排序（降序）。
2. **極端值配對**：將排序後的上午路線與下午路線一一對應，即最長的下午路線配上最短的上午路線。
3. **計算加班費**：遍歷這 $n$ 組配對，如果某組的時數總和大於 $d$，就把價差乘以費率 $r$ 累加到總加班費中。

這種貪婪策略在數學上可以確保將「極端大數值」出現的機率降到最低，從而讓整體的總加班費達到全域最優解。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n, d, r;
    // 當 n, d, r 皆為 0 時結束程式
    while (cin >> n >> d >> r && (n != 0 || d != 0 || r != 0)) {
        vector<int> morning(n);
        vector<int> afternoon(n);

        for (int i = 0; i < n; i++) cin >> morning[i];
        for (int i = 0; i < n; i++) cin >> afternoon[i];

        // 1. 上午路線由小到大排序 (升序)
        sort(morning.begin(), morning.end());

        // 2. 下午路線由大到小排序 (降序)
        sort(afternoon.begin(), afternoon.end(), greater<int>());

        int total_overtime_pay = 0;

        // 3. 貪婪配對並計算加班費
        for (int i = 0; i < n; i++) {
            int total_hours = morning[i] + afternoon[i];
            if (total_hours > d) {
                total_overtime_pay += (total_hours - d) * r;
            }
        }

        cout << total_overtime_pay << endl;
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(N \log N)$。對於每組測試案例，主要的計算瓶頸在於兩次 `std::sort` 排序，其時間複雜度為 $O(N \log N)$。後續用於計算加班費的單層 `for` 迴圈只需 $O(N)$。由於題目限制 $N \le 100$，這個計算量微乎其微，執行時間穩定為 0 毫秒。
- **空間複雜度**：$O(N)$。主要消耗在儲存上午與下午路線時數的兩個 `std::vector`。

## 心得與反思

- **排序不等式的直觀應用**：
  這題背後的數學原理與「排序不等式（Rearrangement Inequality）」非常相似。如果想讓兩個數列兩兩相加並扣除上限後的超額總和最小，將其中一個「正序排列（小到大）」、另一個「反序排列（大到小）」進行極端值配對是最完美的解法。這種「大配小、小配大」的截長補短策略，能最有效地平攤數值，避免產生極端巨大的超時。

- **貪婪演算法的極致簡潔**：
  在競賽中，有些貪婪題目需要非常複雜的嚴格數學證明才能確保正確性，但這題的貪婪思維非常符合生活直覺與人性（讓早上開長途的人下午放鬆一下）。只要能看穿這一層「反向配對」的規律，整題的實作就只剩下兩次排序和一個簡單的線性掃描，程式碼乾淨俐落。
