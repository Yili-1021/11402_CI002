# UVa 11450 - Wedding Shopping

## 問題描述
你要去參加一場婚禮，並帶了 $M$ 元的預算去買衣服。你總共需要購買 $C$ 種不同類型的衣物（例如：上衣、褲子、鞋子等），每種型號的衣服都有幾種不同的款式與價格。

你的任務是從每種衣服類型中**恰好選擇一件**，在不超過總預算 $M$ 的前提下，使得花費的**總金額最大化**。如果不管怎麼組合，預算都不夠買齊這 $C$ 件衣服，則輸出 `no solution`。

---

## 解題邏輯與程式

### 核心邏輯
這是一題非常經典的**動態規劃（Dynamic Programming, DP）**題目，本質上是背包問題（Knapsack Problem）的變形。由於每種衣服「必須且只能選一件」，我們可以用一個二維布林陣列 `dp[i][j]` 來記錄狀態：
- **狀態定義**：`dp[i][j]` 表示在考慮了前 $i$ 種衣服後，是否有可能剛好花費 $j$ 元（`true` 或 `false`）。
- **狀態轉移**：當我們在考慮第 $i$ 種衣服的某個款式，其價格為 `price` 時，如果前一步 `dp[i-1][j-price]` 為真（代表前 $i-1$ 件衣服可以花掉 $j-price$ 元），那麼加上這件衣服後，`dp[i][j]` 就會變成真。
- **邊界與初始條件**：初始時 `dp[0][0] = true`，其餘皆為 `false`。

最後，我們只需要從最大預算 $M$ 開始往回遞減搜尋，找到的第一個讓 `dp[C][money]` 為真的 `money` 就是最優解。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
#include <cstring>
#include <algorithm>
using namespace std;

// dp[i][j] 表示考慮前 i 種衣服後，是否能剛好花費 j 元
bool dp[25][205]; 

int main() {
    int n;
    if (cin >> n) {
        while (n--) {
            int m, c;
            cin >> m >> c;

            // 初始化 DP 陣列
            memset(dp, false, sizeof(dp));
            dp[0][0] = true;

            // 依序讀取每種衣服
            for (int i = 1; i <= c; i++) {
                int k;
                cin >> k;
                while (k--) {
                    int price;
                    cin >> price;
                    
                    // 根據前一個狀態進行轉移
                    for (int j = price; j <= m; j++) {
                        if (dp[i - 1][j - price]) {
                            dp[i][j] = true;
                        }
                    }
                }
            }

            // 從最高預算 M 開始往回找最大花費
            int ans = -1;
            for (int j = m; j >= 0; j--) {
                if (dp[c][j]) {
                    ans = j;
                    break;
                }
            }

            if (ans == -1) {
                cout << "no solution" << endl;
            } else {
                cout << ans << endl;
            }
        }
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(C \times K \times M)$。其中 $C$ 是衣服種類（最多 20），$K$ 是每種衣服的款式上限（最多 20），$M$ 是總預算（最多 200）。三層迴圈的總計算量約為 $20 \times 20 \times 200 = 80,000$ 次基本運算，遠低於 1 秒限制，執行時間通常為 0 毫秒。
- **空間複雜度**：$O(C \times M)$。使用了一個大小為 $25 \times 205$ 的布林陣列。其實也可以透過滾動陣列（Rolling Array）將空間進一步優化到 $O(M)$。

## 心得與反思

- **動態規劃的狀態設計**：
  這題幫我釐清了動態規劃中「求最大值」不一定只能把 `dp` 陣列宣告成 `int` 來存最大錢數。像這題一樣，將金額作為「維度（Index）」，陣列本身只存「可不可行（`bool`）」，有時候反而更容易處理「必須每種都選一件」的限制，這種「可行性轉最值」的思維非常值得借鏡。
  
- **避免貪婪陷阱**：
  這題是一個很好的反例，證明了「貪婪演算法（每次挑最貴或最便宜）」在有預算上限與必須買齊的雙重限制下是行不通的。只有透過動態規劃窮舉所有合法的狀態組合，才能在保障「買齊」的前提下達到「金額最大化」。
