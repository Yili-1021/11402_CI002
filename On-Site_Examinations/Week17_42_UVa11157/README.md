# UVa 11157 - Dynamic Frog

## 問題描述
一隻青蛙想要跨越一條寬度為 $D$ 的大河。河面上散落著 $N$ 顆石頭，每顆石頭都有其特定的座標。這些石頭分為兩種：
- **大石頭（Large Stones，標記為 `L`）**：青蛙可以踩踏無限次，且不會沉沒。
- **小石頭（Small Stones，標記為 `S`）**：青蛙只要踩過一次，該石頭就會立刻**沉入水中**，後續不論是去程還是回程都無法再使用。

青蛙必須先從左岸（座標 0）跳到右岸（座標 $D$），接著再從右岸一路跳回左岸。請規劃一條去程與回程的跳躍路線，使得**整趟往返過程中，「單次跳躍的最大距離」達到最小**，並輸出這個最小化的最大跳躍距離。

---

## 解題邏輯與程式

### 核心邏輯
這是一題結合了**貪婪演算法（Greedy Algorithm）**的精妙題目。

1. **雙軌道思維（去回程對稱）**：
   因為回程時不能踩踏去程已經踩過的小石頭，這本質上等同於：**「有兩隻青蛙要同時從左岸跳到右岸，且它們不能在途中踩到同一顆小石頭」**。大石頭可以被兩隻青蛙同時踩踏，而小石頭則必須被兩隻青蛙平分。
   
2. **交替挑選（貪婪策略）**：
   為了讓每隻青蛙的跳躍距離都盡可能小，當遇到一連串連續的小石頭時，最完美的平分方式就是**交替踩踏**。
   - 青蛙 A（去程）踩第 1, 3, 5... 顆小石頭。
   - 青蛙 B（回程）踩第 2, 4, 6... 顆小石頭。
   而一旦遇到大石頭（`L`），兩隻青蛙都必須強制在該處「會合」，重置它們的立足點。

3. **實作技巧**：
   我們可以用一個陣列依序存入所有的石頭，並在左右兩端（座標 0 與 $D$）各加入一顆虛擬的「大石頭」。接著，我們只需要比較**相鄰一顆石頭**（若是大石頭接小石頭，或大石頭接大石頭）以及**相鄰兩顆石頭**（當連續遇到小石頭時，分流的青蛙會跳過中間那一顆，因此距離是 $i$ 到 $i+2$）的間距，其中的最大值就是答案。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

struct Stone {
    char type;
    int pos;
};

void solve(int case_num) {
    int n, d;
    cin >> n >> d;

    // 建立石頭陣列，並預先加入起點（左岸，視為大石頭）
    vector<Stone> stones;
    stones.push_back({'L', 0});

    for (int i = 0; i < n; i++) {
        string s;
        cin >> s;
        char type = s[0];
        int pos = stoi(s.substr(2));
        stones.push_back({type, pos});
    }
    // 加入終點（右岸，視為大石頭）
    stones.push_back({'L', d});

    int max_jump = 0;

    // 遍歷所有石頭計算可能的最大跳躍距離
    for (size_t i = 0; i < stones.size() - 1; i++) {
        // 狀況 1：看相鄰的下一顆石頭
        max_jump = max(max_jump, stones[i+1].pos - stones[i].pos);

        // 狀況 2：如果下一顆是小石頭，代表其中一隻青蛙會跳過它，改跳到 i+2 的位置
        if (i + 2 < stones.size() && stones[i+1].type == 'S') {
            max_jump = max(max_jump, stones[i+2].pos - stones[i].pos);
        }
    }

    cout << "Case " << case_num << ": " << max_jump << endl;
}

int main() {
    int t;
    if (cin >> t) {
        for (int i = 1; i <= t; i++) {
            solve(i);
        }
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(N)$。每組測試資料中，讀取與建立石頭陣列耗時 $O(N)$。隨後的檢查迴圈只從頭到尾掃描一次陣列，時間複雜度同樣是線性 $O(N)$。因此整體運行速度極快，可在 0 毫秒內輕鬆通過。
- **空間複雜度**：$O(N)$。主要消耗在維護長度為 $N+2$ 的 `std::vector<Stone>` 陣列，記憶體耗費微乎其微。

## 心得與反思

- **將「往返問題」等價轉化為「單向問題」**：
  這題最厲害的破題關鍵在於觀念的翻轉。如果真的傻傻去模擬去程怎麼走、回程怎麼避開，會把狀態搞得極切複雜。但是把「一隻青蛙去、一隻青蛙回」想成「兩隻青蛙手牽手一起過去，但小石頭一人踩一顆」，瞬間就抽離了時間先後的制約，變成一個單純的陣列分流問題。

- **邊界擴充的程式碼美學**：
  在座標 0 和 $D$ 補上虛擬的 `L` 石頭是一個非常精妙的實作細節。如果不補，在程式碼中就必須單獨寫一堆判斷式來算「起點到第一顆石頭」以及「最後一顆石頭到終點」的距離。把它們規格化融入陣列後，一個簡單的 `for` 迴圈就能完美搞定全部的邊界狀況。
