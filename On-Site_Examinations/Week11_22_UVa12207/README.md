# UVa 12207 - That Is Your Queue

## 問題描述
在一個醫療服務系統中，有 $P$ 個居民（編號從 $1$ 到 $P$）正在排隊等待看診。初始狀態下，隊伍是依編號 $1, 2, 3, \dots, P$ 的順序排列。

系統會收到 $C$ 個指令，指令分為以下兩種：
1. `N` (Next)：目前隊伍最前端的人進去進診，並輸出其編號。看診完後，這個人會被重新排到**整條隊伍的最後面**。
2. `E x` (Expedite)：編號為 $x$ 的人是急診病人，他可以直接**插隊到整條隊伍的最前端**。如果 $x$ 本來就在隊伍中，他會移到最前端；如果他剛看完診或不在隊伍前段，一樣直接提到最前面。

請根據指令依序輸出每次 `N` 指令所看診的病人編號。

---

## 邏輯與程式

### 邏輯
1. **處理極大測資規模（$P \le 10^9$）**：
   這題最大的陷阱在於居民人數 $P$ 高達 $10^9$，我們絕對不可能直接開一個大小 $10^9$ 的佇列或陣列來模擬，否則會立即引發 **MLE (記憶體限制超越)** 或 **TLE**。
2. **動態壓縮隊伍長度**：
   雖然總人數很多，但指令數 $C$ 最大只有 $1000$。這意味著在整個過程中，真正會被影響到（插隊或看診）的人數最多只有 $1000$ 人。因此，我們初始只需要將 $\min(P, C)$ 個人放進隊伍中即可。因為排在第 $C$ 個以後的人，如果沒有被急診（`E`）點到，根本不可能在 $C$ 次指令內排到最前面。
3. **善用雙向佇列（std::list / std::deque）**：
   急診指令 `E x` 需要將元素 $x$ 從隊伍中任意位置移出，並塞到隊伍的最前端（`push_front`）。C++ STL 的 `std::list` 支援 $O(1)$ 的前端推入與任意位置刪除，非常適合用來模擬這個特殊的排隊行為。

### 程式
```cpp
#include <iostream>
#include <string>
#include <list>
#include <algorithm>
using namespace std;

int main() {
    int p, c, case_num = 1;
    while (cin >> p >> c && (p != 0 || c != 0)) {
        cout << "Case " << case_num++ << ":" << endl;

        list<int> q;
        // 關鍵優化：人數極大時，最多只需要把前 c 個人放進初始隊伍
        int limit = min(p, c);
        for (int i = 1; i <= limit; i++) {
            q.push_back(i);
        }

        while (c--) {
            char cmd;
            cin >> cmd;
            if (cmd == 'N') {
                // 取出隊伍最前端的病人
                int current = q.front();
                cout << current << endl;
                q.pop_front();
                // 看診完後排到隊伍最後面
                q.push_back(current);
            } 
            else if (cmd == 'E') {
                int x;
                cin >> x;
                // 如果這個人本來就在我們維護的隊伍中，先將他移除
                q.remove(x);
                // 直接插隊到最前端
                q.push_front(x);
            }
        }
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：
  - **初始化**：$O(\min(P, C))$，每組測資最多只會將前 $C$ 個元素推入 list。
  - **指令處理**：`N` 指令為 $O(1)$；`E x` 指令因為需要使用 `q.remove(x)` 線性搜尋該元素，時間複雜度為 $O(K)$（$K$ 為當前 list 的長度，最大不超過 $C$）。由於 $C \le 1000$，總體運作時間極快，大約幾毫秒即可通過。
- **空間複雜度**：$O(\min(P, C))$。list 中最多同時存在 $C$ 個左右的元素，完美避開了 $10^9$ 的記憶體空間坑。

## 心得與反思

- **離散化與動態壓縮思維**：
  這題是非常經典的「空間優化」題目。面對 $10^9$ 的天文數字，直覺式的暴力模擬一定會崩潰。學會分析「指令上限 `C`」與「資料範圍 `P`」之間的關係，並發現「大部份的居民根本輪不到看診」，進而只將必要的元素納入考慮，是演算法優化中非常高級且實用的思維。
