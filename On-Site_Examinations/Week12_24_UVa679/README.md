# UVa 679 - Dropping Balls

## 問題描述
有一棵滿二元樹（Full Binary Tree），深度為 $D$，節點由上到下、由左到右依序編號為 $1, 2, 3, \dots, 2^D-1$。每個節點都有一個開關（Switch），初始狀態全部為 `false`（關閉，代表球經過時會往**左**掉落）。

當有一顆球從根節點（節點 1）掉落時，它會依據當前節點的開關狀態決定走向：
- 如果開關為 `false`：球往**左子樹**掉落，並將該節點開關切換為 `true`。
- 如果開關為 `true`：球往**右子樹**掉落，並將該節點開關切換為 `false`。

現在依序放下一共 $I$ 顆球，請計算出**第 $I$ 顆球**最後會落在哪一個葉子（Leaf）節點上？

---

## 解題邏輯與程式

### 核心邏輯
如果直接使用陣列去暴力模擬每顆球的掉落軌跡，時間複雜度會高達 $O(I \times D)$，在測資龐大時必定會超時（TLE）。

本題的精髓在於**只關注最後第 $I$ 顆球**，並利用球數進入節點的**奇偶性（Parity）**直接推算它的下落路徑：
1. **二元樹索引規律**：若當前節點編號為 `k`，其左子節點為 `2 * k`，右子節點為 `2 * k + 1`。
2. **奇數顆球**：當第 $I$ 顆球是奇數（$I \% 2 == 1$）通過某節點時，此時開關必定為關閉狀態，球會往**左**走。對於左子樹而言，它是第 $(I+1)/2$ 顆掉進來的球。
3. **偶數顆球**：當第 $I$ 顆球是偶數（$I \% 2 == 0$）通過某節點時，此時開關已被前一顆球打開，球會往**右**走。對於右子樹而言，它是第 $I/2$ 顆掉進來的球。

透過這個規律，我們只需要從根節點開始，依據 $I$ 的奇偶性不斷修正 $I$ 的值並向下移動 $D-1$ 步，即可在 $O(D)$ 的極致時間內直接求出終點。



### 完整程式碼
```cpp
#include <iostream>
using namespace std;

int main() {
    int l; // 測試資料組數
    if (cin >> l) {
        while (l--) {
            int d, i;
            cin >> d >> i;

            int k = 1; // 從根節點 1 開始
            // 深度為 d 的樹，需要向下走 d-1 步到達葉子節點
            for (int step = 0; step < d - 1; step++) {
                if (i % 2 == 1) { 
                    // 奇數顆球，往左子樹走
                    k = 2 * k;
                    i = (i + 1) / 2; // 更新為掉入左子樹的球數序號
                } else { 
                    // 偶數顆球，往右子樹走
                    k = 2 * k + 1;
                    i = i / 2;       // 更新為掉入右子樹的球數序號
                }
            }
            cout << k << endl;
        }
        // 讀取最後的結尾標記 -1
        int stop;
        cin >> stop;
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(D)$。對於每組測資，我們不需要管前面 $I-1$ 顆球的去向，只需要跟著第 $I$ 顆球的邏輯往下走 $D-1$ 步。因為題目限制 $D \le 20$，迴圈最多跑 20 次，複雜度是極低的常數時間。
- **空間複雜度**：$O(1)$。不需要建立整棵二元樹陣列，僅使用常數個變數進行路徑追蹤，極度節省記憶體。

## 心得與反思

- **捨棄直覺模擬，尋找核心數學規律**：
  這題是非常震撼的「模擬轉數學」經典題。一開始很容易被題目中「大量球落下與開關切換」的敘述帶偏，試圖用大陣列去暴力模擬。但透過觀察奇偶數的分流規律，發現每一層的決策只取決於進入該節點的球是第幾顆，從而將大型模擬優化成了極簡的數學推導。
  
- **深刻理解二元樹的索引性質**：
  這次實作讓我對二元樹中 `2 * k` 和 `2 * k + 1` 的節點編號移動更加直觀。在演算法中，有時候「不把結構真的建出來（不建樹、不開陣列）」反而才是最高效、最省空間的精妙解法。
