# UVa 900 - Brick Wall Patterns

## 問題描述
我們想要用大小為 $1 \times 2$ 的紅磚，拼湊出一個高度固定為 2、長度為 $N$ 的磚牆（即總面積為 $2 \times N$）。

由於每一塊紅磚都可以選擇**橫著放（佔據 $1 \times 2$ 的空間）**或**直著放（佔據 $2 \times 1$ 的空間）**，因此隨著牆壁長度 $N$ 的增加，拼湊出牆壁的圖案組合數也會隨之改變。
請計算出給定長度 $N$ 時，總共能創造出多少種截然不同的牆壁圖案？

---

## 解題邏輯與程式

### 核心邏輯
這是一題非常經典的**動態規劃（Dynamic Programming）**與遞迴入門題，其本質就是經典的**費氏數列（Fibonacci Sequence）**。

我們可以透過列舉較小的 $N$ 來觀察規律：
- 當 $N = 1$ 時：只能直放 1 塊紅磚，共 **1** 種圖案。
- 當 $N = 2$ 時：可以放 2 塊直的，或 2 塊橫的，共 **2** 種圖案。
- 當 $N = 3$ 時：可以從 $N=2$ 的結尾再加 1 塊直的（2 種），或從 $N=1$ 的結尾再加 2 塊橫的（1 種），共 2 + 1 = **3** 種圖案。



**狀態轉移公式**：
對於長度為 $N$ 的牆壁，它的最後一步只有兩種可能：
1. 最後一列是由 **1 塊直放的紅磚** 組成。這種情況下，前面的長度為 $N-1$，組合數為 $f(N-1)$。
2. 最後兩列是由 **2 塊橫放的紅磚（上下並排）** 組成。這種情況下，前面的長度為 $N-2$，組合數為 $f(N-2)$。

因此，長度 $N$ 的總組合數為：
$$f(N) = f(N-1) + f(N-2)$$
基底條件為 $f(1) = 1, f(2) = 2$。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    // 題目上限 N <= 50，第 50 項費氏數列會超出 32 位元整數 (int) 的範圍
    // 因此必須使用 long long 來防止整數溢位 (Integer Overflow)
    long long fib[51];
    fib[1] = 1;
    fib[2] = 2;

    // 1. 建表預處理 (Bottom-up DP)
    for (int i = 3; i <= 50; i++) {
        fib[i] = fib[i - 1] + fib[i - 2];
    }

    int n;
    // 2. 線性時間查表輸出
    while (cin >> n && n != 0) {
        cout << fib[n] << endl;
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(N)$。在程式剛開始時，我們透過一個簡單的 `for` 迴圈預先計算並建立到第 50 項的費氏數列查表（建表耗時 $O(N)$，此處 $N=50$ 為常數）。隨後的每組測試資料輸入，都可以在 $O(1)$ 的時間內直接查表輸出答案。
- **空間複雜度**：$O(N)$。僅開闢了一個長度為 51 的 `long long` 陣列來儲存預建的表格，記憶體消耗微乎其微。

## 心得與反思

- **整數溢位（Overflow）的防範意識**：
  這題雖然邏輯十分簡單，但暗藏了一個新手極易踩中的陷阱。費氏數列的增長速度呈指數級別，第 47 項之後的數值就已經超越了標準 `int` 的最大上限（$2 \times 10^9$）。這題強迫我們在思索演算法之餘，必須時刻對資料型態（Data Type）的邊界保持敏感度，靈活切換成 `long long`。

- **動態規劃的建表優化（Memoization）**：
  如果對每個詢問 $N$ 都重新用遞迴計算 `fib(n) = fib(n-1) + fib(n-2)`，會導致大量重疊子問題被重複計算，時間複雜度暴增到 $O(2^N)$。透過由底向上（Bottom-up）的建表預處理，把問題轉化為單純的陣列加法，用極小的空間換取了完美的線性執行效率。
