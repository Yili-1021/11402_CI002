# UVa 10359 - Tiling

## 問題描述
我們想要用兩種不同規格的磁磚來鋪滿一個大小為 $2 \times n$ 的矩形區域。可用的磁磚規格如下：
1. **$2 \times 1$ 的矩形磁磚**（可以直放佔據 $2 \times 1$，也可以橫放佔據 $1 \times 2$）
2. **$2 \times 2$ 的正方形磁磚**

請計算出給定長度 $n$ 時，總共能創造出多少種截然不同的鋪設圖案？

---

## 解題邏輯與程式

### 核心邏輯
這題是經典的**動態規劃（Dynamic Programming）**題目，本質上是費氏數列（Fibonacci）的變形延伸。

我們可以透過結構的最後一步來推導**狀態轉移公式**。對於一個 $2 \times n$ 的矩形，其最右側的邊界拼法只有以下三種可能：
1. 最右邊放 **1 塊直立的 $2 \times 1$ 磁磚**：此時左邊剩下的區域大小為 $2 \times (n-1)$，組合數為 $f(n-1)$。
2. 最右邊放 **2 塊橫躺的 $2 \times 1$ 磁磚（上下並排）**：此時左邊剩下的區域大小為 $2 \times (n-2)$，組合數為 $f(n-2)$。
3. 最右邊放 **1 塊 $2 \times 2$ 的正方形磁磚**：此時左邊剩下的區域大小為 $2 \times (n-2)$，組合數為 $f(n-2)$。



將以上三種不重疊的狀況加總，即可得到轉移方程：
$$f(n) = f(n-1) + 2 \times f(n-2)$$
基底條件為：
- $f(0) = 1$（空矩形算 1 種拼法）
- $f(1) = 1$
- $f(2) = 1 + 2 \times 1 = 3$

### 大數運算（Big Integer）
本題的 $n$ 最大可達 $250$。根據公式的指數級增長速度，$f(250)$ 的結果會是一個大約 70 幾位的超大整數，早就遠遠超過了 C++ 中 `long long` 的最大負荷（約 19 位數）。因此，我們必須手寫**大數加法（Big Integer Addition）**來完成動態規劃的建表。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

// 實作大數加法：c = a + b
string add(string a, string b) {
    string res = "";
    int i = a.length() - 1, j = b.length() - 1;
    int carry = 0;

    while (i >= 0 || j >= 0 || carry) {
        int sum = carry;
        if (i >= 0) sum += a[i--] - '0';
        if (j >= 0) sum += b[j--] - '0';
        carry = sum / 10;
        res += to_string(sum % 10);
    }
    reverse(res.begin(), res.end());
    return res;
}

int main() {
    // 1. 預處理建表：題目上限 N <= 250
    vector<string> dp(251);
    dp[0] = "1";
    dp[1] = "1";

    for (int i = 2; i <= 250; i++) {
        // f(i) = f(i-1) + 2 * f(i-2)
        // 2 * f(i-2) 可以拆解成 f(i-2) + f(i-2)
        string two_times_prev2 = add(dp[i-2], dp[i-2]);
        dp[i] = add(dp[i-1], two_times_prev2);
    }

    int n;
    // 2. $O(1)$ 時間查表輸出
    while (cin >> n) {
        cout << dp[n] << endl;
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(N^2)$。預處理建表共有 $N$ 個狀態（$N=250$）。由於每個狀態涉及字串形式的大數加法，其長度與 $N$ 成正比（最長約 76 位數），故每次加法耗時 $O(N)$。總建表時間為 $O(N^2)$。建表完成後，每組測資查表輸出的時間為 $O(1)$。整體執行時間在 0 毫秒內。
- **空間複雜度**：$O(N^2)$。我們維護了一個長度為 $251$ 的 `std::vector<string>`，其中每個字串的最大長度不超過 80 個字元，記憶體耗費極低。

## 心得與反思

- **大數邏輯的解題防禦**：
  這題是從費氏數列（UVa 900）走向大數 DP 的經典分水嶺。在演算法競賽中，當看到轉移方程具有成倍增長的遞迴特性（如本題的 $2 \times f(n-2)$），且範圍給到 100 以上時，就必須立刻拉響大數溢位的警報，並熟練地套用字串加法模板，才能穩健地拿到 AC。

- **乘法化為加法的代數技巧**：
  在實作 $2 \times f(n-2)$ 時，如果為了這個「乘 2」再去寫一個大數乘法的函式，會讓程式碼變得臃腫。利用代數概念將其拆解為 `add(dp[i-2], dp[i-2])`，直接復用現成的大數加法功能，是讓程式碼保持精簡、減少出錯率的工程小智慧。
