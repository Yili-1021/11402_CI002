# UVa 10821 - Constructing BST

## 問題描述
給定由小到大連續的 $N$ 個正整數（即 $1, 2, 3, \dots, N$），我們想用這些數字構造出一棵二元搜尋樹（BST）。這棵樹的高度（Height）不能超過 $H$。

由於符合這種高度限制的二元搜尋樹可能有很多種，題目要求我們輸出**前序走訪（Pre-order Traversal）具有最小字典序（Lexicographically Smallest）**的那棵樹。如果無論如何都無法在高度 $H$ 限制內放入 $N$ 個節點，則輸出 `Impossible.`。

---

## 解題邏輯與程式

### 核心邏輯
前序走訪的順序是：**根節點 $\rightarrow$ 左子樹 $\rightarrow$ 右子樹**。
為了讓前序走訪的「字典序最小」，我們在挑選當前子樹的根節點時，**應該盡可能挑選越小的數字越好**。

然而，挑選的根節點如果太小，會導致剩下的絕大多數數字都被迫分到「右子樹」。右子樹在有限的高度限制 $H-1$ 下，所能容納的最大節點數是有上限的：
- 一棵高度為 $h$ 的二元樹，最多只能容納 $2^h - 1$ 個節點。

因此，貪婪策略的精髓在於：
1. **保留最大容納量給右子樹**：假設當前子樹總共有 `total` 個節點，高度限制為 `h`。它的右子樹在高度 `h-1` 的限制下，最多可以容納 `max_right = (1 << (h - 1)) - 1` 個節點。
2. **挑選最優根節點**：為了留足夠的數字給右子樹，左子樹與根節點分到的節點數最少必須是 `total - max_right`。因為我們希望根節點越小越好，所以應該剛好把剩餘的數字全塞給右子樹。因此，當前根節點在陣列中的相對位置應該選在 `max(1, total - max_right)`（相對於當前範圍）。
3. **分治遞迴**：輸出選定的根節點後，將範圍切分為左子樹與右子樹，高度限制一律減 $1$（即 `h - 1`），繼續遞迴。

### 完整程式碼
```cpp
#include <iostream>
#include <algorithm>
using namespace std;

// s: 當前範圍的起點數字, e: 當前範圍的終點數字, h: 當前允許的最大高度
void solve(int s, int e, int h) {
    if (s > e) return;

    int total_nodes = e - s + 1;
    
    // 在高度 h - 1 的限制下，右子樹最多能容納的節點數
    // 使用 min(h-1, 30) 防止位移運算超過 int 上限
    int max_right_capacity = (1 << min(h - 1, 30)) - 1;

    // 為了讓右子樹放得下，根節點左側(含根節點自己)必須保留的最小節點數
    int root_offset = max(1, total_nodes - max_right_capacity);

    // 決定當前根節點的數值
    int root_val = s + root_offset - 1;

    // 前序走訪：先輸出根節點
    cout << " " << root_val;

    // 遞迴處理左子樹與右子樹，高度限制皆減 1
    solve(s, root_val - 1, h - 1);
    solve(root_val + 1, e, h - 1);
}

int main() {
    int n, h, case_num = 1;
    while (cin >> n >> h && (n != 0 || h != 0)) {
        cout << "Case " << case_num++ << ":";

        // 如果總節點數大於高度 h 能容納的最大滿二元樹節點數，則無解
        if (h < 31 && n > (1 << h) - 1) {
            cout << " Impossible." << endl;
        } else {
            solve(1, n, h);
            cout << endl;
        }
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(N)$。每組測試資料共有 $N$ 個節點，每個節點都在遞迴中被當作根節點處理且輸出一次。每次計算根節點的位置只需要 $O(1)$ 的位移與數學運算，因此總時間複雜度為線性的 $O(N)$。
- **空間複雜度**：$O(H)$。不需要實際建立樹狀圖，空間消耗主要來自遞迴時系統 stack 的深度，最深等於樹的高度 $H$。

## 心得與反思

- **貪婪演算法與邊界限制的平衡**：
  這題是非常漂亮的貪婪（Greedy）與分治法結合。直覺上要讓前序字典序最小，應該每一步都無腦選最小的數字當根節點。但這題加上了「高度限制」，逼得我們必須「一邊貪婪，一邊精算右子樹的極限容量」。這種在危險邊緣試探、剛好滿足邊界條件的解題思維非常精彩。
  
- **極值防禦程式設計**：
  在實作 `1 << (h - 1)` 時，必須注意到題目中 $H$ 可能會給到很大（例如大於 30）。如果直接進行 `1 << 60` 會導致整數溢位（Overflow）進而產生錯誤的容量計算。透過 `min(h - 1, 30)` 來進行防禦性設限，可以確保程式在大測資下的安全性。
