# UVa 11292 - Dragon of Loowater

## 問題描述
王國遭到了惡龍的襲擊！這隻惡龍擁有 $n$ 個頭。為了拯救王國，國王決定僱用騎士來砍掉惡龍的頭。王國裡有 $m$ 個騎士，每位騎士都有特定的身高（代表其戰力），且每位騎士**只能砍掉一個直徑小於或等於他身高的龍頭**。

僱用某位騎士的費用（金幣）在數值上恰好等於他的身高。請計算出，在成功砍掉惡龍所有頭的前提下，國王最少需要花費多少金幣？如果王國裡的騎士不夠強，或者人數不足以砍掉所有的頭，請輸出 `Loowater is doomed!`。

---

## 解題邏輯與程式

### 核心邏輯
這是一題非常典型的**貪婪演算法（Greedy Algorithm）**題目，核心在於如何以最經濟實惠的代價消滅敵人：

1. **雙重排序**：首先將惡龍所有頭的直徑由小到大排序，同時也將所有騎士的身高（戰力與費用）由小到大排序。
2. **貪婪配對**：由小到大依序處理每隻惡龍的頭。對於當前這個「最小的龍頭」，我們要在騎士陣容中，**由小到大尋找第一個身高大於或等於該龍頭直徑的騎士**。
3. **策略正確性**：為什麼這是最優解？因為用剛好夠強（最矮）的騎士去砍當前的龍頭，就能把更強（更高、更貴）的騎士保留給後面更大的龍頭，從而確保總花費最小。
4. **結束條件**：
   - 如果順利把所有龍頭都配對完畢，則輸出累積的總金幣。
   - 如果所有騎士都看遍了，卻還有龍頭沒被砍掉，代表防線崩潰，輸出 `Loowater is doomed!`。

### 完整程式碼
```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n, m;
    // 當 n 和 m 皆為 0 時結束程式
    while (cin >> n >> m && (n != 0 || m != 0)) {
        vector<int> dragon(n);
        vector<int> knight(m);

        for (int i = 0; i < n; i++) cin >> dragon[i];
        for (int i = 0; i < m; i++) cin >> knight[i];

        // 1. 將龍頭直徑與騎士身高進行排序
        sort(dragon.begin(), dragon.end());
        sort(knight.begin(), knight.end());

        int d_idx = 0; // 龍頭的指針
        int k_idx = 0; // 騎士的指針
        long long total_gold = 0;

        // 2. 使用雙指針進行貪婪配對
        while (d_idx < n && k_idx < m) {
            if (knight[k_idx] >= dragon[d_idx]) {
                // 騎士足夠強，僱用他砍掉這顆頭
                total_gold += knight[k_idx];
                d_idx++; // 處理下一顆龍頭
            }
            k_idx++; // 不論騎士有沒有被僱用，指針都往後移（因為排序過，前面的騎士太矮派不上用場了）
        }

        // 3. 判斷是否成功砍完所有龍頭
        if (d_idx == n) {
            cout << total_gold << endl;
        } else {
            cout << "Loowater is doomed!" << endl;
        }
    }
    return 0;
}
```
## 複雜度分析

- **時間複雜度**：$O(N \log N + M \log M)$。主要的效能瓶頸在於對龍頭與騎士陣列進行排序，分別耗時 $O(N \log N)$ 與 $O(M \log M)$。隨後的雙指針線性掃描只需 $O(N + M)$。對於題目上限 $N, M \le 20000$，總運算量在百萬等級以內，可在幾毫秒內超高速通過。
- **空間複雜度**：$O(N + M)$。主要消耗在儲存龍頭直徑與騎士身高的兩個 `std::vector`。

## 心得與反思

- **雙指針在排序資料上的奇效**：
  這題展示了「先排序，後指針」的強大威力。如果數據雜亂無章，我們每看到一個龍頭就要去騎士堆裡撈人，很容易退化成 $O(N \times M)$。但是一旦雙方都排好序，我們只要用兩個指針一路往右走、永不回頭，就能以 $O(N + M)$ 的線性時間完成全域最佳配對。

- **貪婪決策的直觀展現**：
  在競賽中，有些貪婪題目需要複雜的數學證明，但這題的貪婪思維非常符合人類的直覺——「殺雞焉用牛刀，砍小龍不用大騎士」。透過這題的練習，能更加熟悉如何將這種「能省則省，留牌打後面」的局部最優策略轉化為簡潔的雙指針程式碼。
